# Meridian 分析技能

技能是**声明式的分析配方**,不是代码插件。一份 `skill.json` 描述:遇到这类文件时,必须问哪些
子问题、必须算哪些数、必须检查哪些风险、哪些表述必须归因、哪些措辞在这个题材下额外禁用。

## 技能能做什么、不能做什么

技能可以让管线**多问、多算、多查**;它**不能让管线多断言**。

技能贡献的一切仍然要过七步管线的全部关卡:引文必须在原文中逐字定位,数字必须绑定到引文或
管线自算的派生数,模型推断必须找到反方证据才能发表,产出整体过合规闸。技能的 `forbidden_reinforce`
只叠加在全局禁令之上,**不能减免任何一条**。

## 契约

```jsonc
{
  "id": "impairment-readout",
  "version": "0.1",
  "fallback": false,                    // 仅兜底技能为 true,全局有且只有一个
  "match": {
    "doc_keywords": ["计提减值"],        // 出现在原文里的词
    "question_keywords": ["减值"]        // 出现在用户提问里的词(权重更高)
  },
  "sub_questions": ["……"],               // 中性措辞铁律,见下
  "required_derivations": [              // 期望「算出来」而非「抄出来」的数
    { "name": "最大单项占合计比例", "formula_hint": "该项金额 / 各项合计金额" }
  ],
  "risk_checklist": ["……"],              // 每项须在 memo 里有着落,否则记审计并写入 memo.checklist
  "counterevidence_slots": ["……"],       // 值得找反方证据的推断方向
  "attribution_flags": ["……"],           // 这类文件里习惯被当成事实的自述
  "forbidden_reinforce": ["买入时点"]     // 技能级禁语(短语,不是句子)
}
```

## 两条硬规则

**一、子问题必须中性。** 不得把某一种结局写进问题:问「目前处于哪个阶段」,不问
「是否已受理」。原因有二:带预设的提问会把抽取往那个方向带;而子问题会被原样用作备忘录的
章节标题,一个预设状态在标题里读起来就是断言。校验器会拒绝这类措辞。

**二、配方里不写数字。** 技能是可复用的方法,不是某一份公告的答案。任何具体数字都说明某个
案例的结论漏进了本该通用的方法里。校验器拒绝含数字的配方内容;`agent/test/skills.test.ts`
另外断言技能内容与 `bench/tasks/*/gold.json` 不共享任何长片段——**把金标准答案写进技能就是
作弊**(见 CONTRIBUTING 诚实基准条款)。

## 匹配与使用

不指定时,管线按关键词打分自动选择(提问命中权重 2,原文命中权重 1),都不命中则用兜底技能
`filing-quick-read`。所用技能与版本记入 `memo.provenance.skill`。

```sh
meridian ask "本期计提了多少减值准备?" --file 公告.txt              # 自动匹配
meridian ask "这次减持是谁在卖?" --file 公告.txt --skill buyback-selldown  # 显式指定
```

## 官方技能

| id | 适用 | 关键判别 |
|---|---|---|
| `filing-quick-read` | 兜底通用 | 事实、关键数字、程序状态、风险与自述归因 |
| `impairment-readout` | 计提减值 | 明细与合计、对净利与权益的影响、最大项占比(派生)、审计状态 |
| `restructuring-status` | 破产重整 | 「申请」与「受理」严格区分、退市风险叠加、跨文档时间线 |
| `placement-terms` | 向特定对象发行 | 定价规则≠已定价、数量上限双口径、尚需程序清单 |
| `buyback-selldown` | 回购与库存股处置 | 处置主体判别(公司≠股东)、回购均价(派生)、处置溢价(派生链) |
